Devlog 000, Before the Repository

May 2026 · Origin notes · Mnemosyne

Before Mnemosyne was a repository, it was frustration.

I was using AI roleplay platforms, trying different bots, different prompts, different formats, and eventually different AI coding tools. At first, I thought the problem was just that I needed a better prompt. Then I realized the problem was deeper.

The AI could write a dramatic scene. It could imitate emotion. It could produce a good moment. But it could not always live through that moment.

Characters changed too fast. Trust jumped too quickly. Fear disappeared because the scene needed to move forward. Shame got solved by one good speech. A character could go from guarded to devoted in a handful of messages, not because the relationship had earned it, but because the model wanted to satisfy the current direction of the scene.

That broke the illusion for me.

I did not want a character that only reacted well in the moment. I wanted a character that carried the weight of what had happened before.

My first solution was crude. I made prompt-based tracking systems. At the end of the chat, I had the AI append a compact code block, almost like a little scene compile format. It tracked things like status, scene state, memories, atmosphere, physical condition, sensory details, and character position.

It was not a state engine. It was not a database. It was not a proper memory system. It was just a code block.

But it worked better than nothing, and that bothered me even more. If a rough code block could improve continuity, then the missing piece was probably not just better prose. The missing piece was structure.

The AI needed memory outside normal narration.

Not just a summary. Not just a longer context window. Not just “remember this character likes coffee.” I wanted something closer to a Soul: a compact record of what changed inside a character over time.

Trust should not be the same as affection. Fear should not be the same as shame. Attraction should not be the same as commitment. A character can like someone and still distrust them. They can feel safe in one place and terrified in another. They can forget an ordinary conversation but remember one small sentence forever because it hit the right wound.

That became the first real shape of the idea.

A universal character state tracker. Something genre-agnostic enough to work for a dating sim, a Minecraft NPC, a fantasy companion, a robot, a villain, or a long-form roleplay character. The genre did not matter. The foundation was the same: a character should not be a static prompt. A character should evolve.

The second problem was memory quality.

I did not trust platform auto-summaries. They often flattened the wrong things, skipped important emotional turns, or preserved facts without preserving meaning. My workaround was manual: copy the whole chat, paste it into another model, and ask it to summarize the session myself.

That worked better, but it was still manual labor. It also proved something important: a memory system should not save everything equally.

Humans do not remember like databases. We forget most things. We keep fragments. We keep emotional landmarks. We remember what surprised us, hurt us, helped us, threatened us, or changed how we saw someone.

So the idea shifted again.

Mnemosyne was not supposed to be a transcript machine. It was supposed to track what mattered.

Make the AI remember like a character, not like a transcript.

That led to the flagging idea. Important events and dialogue should be marked based on character-specific salience. A betrayal matters more to a character who values loyalty. A small act of protection matters more to someone who has not felt safe. A casual joke might vanish, but the same joke said during fear or grief might become unforgettable.

The system needed to decide what a character would remember, what they would misremember, and what they would forget.

It also needed to let characters grow slowly. No instant trust. No instant healing. No emotional teleportation. If a relationship changed, the system had to ask: was there enough time, enough evidence, enough pressure, enough consistency? If not, the character should resist the change, even if the scene wanted it.

That was when the project stopped being “I need a better RP prompt.”

What would it take to make AI character memory feel human?

From there, the shape of Mnemosyne started to form. Not all at once. Not as a clean architecture diagram. It started as a crude tracking block, then a hidden status format, then a thought about memory flags, then a larger idea about Souls and continuity.

At this point, there was no polished app. No clean UI. No roadmap. No alpha. No domain. No proper repository history yet.

There was only the feeling that the current platforms were not enough, and that maybe the fix was not another character card. Maybe it was an engine.

That is where Mnemosyne started.

Not with code. With a code block that got out of hand.
